# 05 · 验签与交付

打出一个 `.apk` 文件不等于它能装。交付前跑一遍 `scripts/verify.sh`，三段检查各管一件事。

```bash
bash scripts/verify.sh out/hello.apk
```

## 1/3 · 签名校验

```bash
apksigner verify --verbose out/hello.apk
```

本机实测：

```
Verifies
Verified using v1 scheme (JAR signing): true
Verified using v2 scheme (APK Signature Scheme v2): true
Verified using v3 scheme (APK Signature Scheme v3): true
Number of signers: 1
```

- `Verifies` 是总判定，必须出现。
- v1 保证 Android 6 及更早设备能装；v2/v3 保证新设备的完整性校验。三者全开最稳。
- v3.1 / v4 / SourceStamp 为 false 属正常，那些是特定分发渠道才用的。
- 打印证书用 `apksigner verify --print-certs`，能核对 DN 与 SHA-256 指纹。

## 2/3 · 清单与版本

```bash
aapt2 dump badging out/hello.apk
```

本机实测：

```
package: name='dev.example.helloweb' versionCode='1' versionName='1.0'
sdkVersion:'21'
targetSdkVersion:'34'
application-label:'Hello WebView'
launchable-activity: name='dev.example.helloweb.MainActivity'
```

重点核对：包名、`versionCode` / `versionName`（是否由 `--version-code` 正确注入）、`minSdk` / `targetSdk`、以及**存在可启动的 Activity**。没有 `launchable-activity` 通常意味着 Manifest 的 intent-filter 或 `exported` 写错了。

## 3/3 · 包内容

```bash
unzip -l out/hello.apk
```

本机实测关键条目：

```
AndroidManifest.xml
resources.arsc
assets/index.html
classes.dex
```

如果前端页面没进去，多半是 `aapt2 link` 漏了 `-A app/src/main/assets`；如果 `classes.dex` 不在，检查第 4/5 步。

## 安装

```bash
adb install -r out/hello.apk
```

- 自签名应用会提示「未知来源」，属正常，需要用户在系统设置里允许该来源。
- `adb install -r` 覆盖安装时若报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，是签名不一致（换了 keystore）。
- 真机上重点看四件事：启动有没有白闪、系统深色下颜色有没有被反转、返回键行为、以及杀进程后数据还在不在。这四项对应 [03 · WebView 壳适配](03-WebView壳适配.md) 的四条适配。

## 升级覆盖的两条铁律

1. **同一包名必须用同一把 keystore 与同一个别名**。签名变了只能卸载重装，用户数据会丢。把 keystore 和密码管理器放在一起，别放进仓库（`.gitignore` 已排除 `*.jks`）。
2. **`versionCode` 必须递增**，`versionName` 只是给人看的。用环境变量传：

```bash
APP=examples/hello-webview NAME=hello VERSION_CODE=2 VERSION_NAME=1.1 bash build_apk.sh
```

## 体积参考

| 组成 | 典型体积 |
|---|---|
| 纯 WebView 壳（本仓库示例，含 5 档图标与页面） | 44 KB |
| 加上数百条内置发音 | ~3 MB |
| Android Studio 空模板（对照） | 1.5–3 MB |

手工链的体积优势来自「没有 AndroidX、没有 Kotlin 标准库、没有多余的构建产物」，不是靠压缩技巧。
