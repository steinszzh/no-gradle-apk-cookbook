# 01 · 六步链

Gradle 遮住的其实只有六个动作。把它们拆开之后，每一步的输入、输出、报错位置都是可见的——这正是手工链最大的价值。

| 步 | 工具 | 输入 | 输出 | 出错通常意味着 |
|---|---|---|---|---|
| 1 | `aapt2 compile` | `res/` | `*.flat` | XML / 图片资源写错 |
| 2 | `aapt2 link` | `*.flat` + Manifest + `android.jar` | `base.apk` + `R.java` | 清单、包名、资源引用、`@style` 引用有问题 |
| 3 | `javac` | `*.java` + `R.java` | `*.class` | Java 代码、API level、`android.jar` 不匹配 |
| 4 | `d8` | `*.class` | `classes.dex` | 字节码版本、依赖缺失、方法数 |
| 5 | `zip` + `zipalign` | `base.apk` + `classes.dex` | `aligned.apk` | 顺序错 / 产物被改动 |
| 6 | `apksigner` | `aligned.apk` + keystore | 签名 APK | 别名、口令、签名方案 |

对应到仓库里就是 `build_apk.sh` 的六段，可直接对照源码读。

## 1 · aapt2 compile

```bash
"$BT/aapt2" compile --dir "$APP/res" -o "$OUT/res"
```

`--dir` 会把整个 `res/` 编译成一批 `.flat`（文件名带目录前缀，如 `values_colors.arsc.flat`），平铺在输出目录里。**`-o` 指定的目录必须已存在**，脚本里已经 `mkdir -p`。

只想增量编译可用单文件形式 `aapt2 compile res/values/strings.xml -o compiled/`；`--dir` 没有增量优势，但对小项目无所谓。

## 2 · aapt2 link

```bash
aapt2 link -o out/base.apk \
  -I "$SDK"/platforms/android-35/android.jar \
  --manifest app/src/main/AndroidManifest.xml \
  --java out/gen \
  --min-sdk-version 21 --target-sdk-version 34 \
  --version-code 1 --version-name 1.0 \
  -A app/src/main/assets \
  out/res/*.flat
```

要点：

- `-I` 指向 `android.jar`，框架资源 ID 从这里来。
- `--java out/gen` 生成 `R.java`，**必须一起交给下一步的 `javac`**，否则代码里引用 `R.*` 会编译不过；本仓库示例的 Java 不引用 `R`，但脚本仍会把它编译进去。
- 版本号用命令行注入，Manifest 里就不必写 `versionCode` / `versionName`，避免两处不一致。
- `-A` 把 `assets/` 原样塞进 APK，前端的 `index.html`、css、js、音频全靠它，走 `file:///android_asset/index.html` 加载。

## 3 · javac

```bash
javac -nowarn -source 8 -target 8 -encoding UTF-8 \
      -bootclasspath "$AJAR" -d out/classes \
      app/src/main/java/**/*.java out/gen/**/*.java
```

- `-bootclasspath` 用 `android.jar` 替换 JDK 的 `rt.jar`，这样 `android.*` 才能解析。JDK 17 会提示 bootstrap class path 未与 `-source 8` 一起设置之类警告，不影响产物。
- **别在这里用 lambda**：`-bootclasspath android.jar` 下 javac 找不到 `LambdaMetafactory`，会报 `cannot find symbol metafactory`。用匿名内部类（示例里的 `ValueCallback`）即可，详见 [02 · 环境坑](02-环境坑.md)。

## 4 · d8

```bash
"$BT/d8" --release --lib "$AJAR" --min-api 21 --output out/dex out/classes/**/*.class
```

- `--lib` 与 `--min-api` 要和第 2、3 步保持一致。
- `--release` 去掉调试信息、体积更小；调试阶段可以去掉，或换 R8 做 shrink。
- 输出固定是 `out/dex/classes.dex`。

## 5 · zip + zipalign

```bash
(cd out/dex && zip -q -X "$OUT_ABS/base.apk" classes.dex)
"$BT/zipalign" -f -p 4 out/base.apk out/aligned.apk
```

- `zip -X` 去掉额外字段，保持条目干净。
- `-p 4` 让未压缩的 `.so` 等按 4 字节页对齐；**Android 11+ 强制要求 `zipalign` 在签名之前完成**。
- 顺序铁律：`link → 加 dex → zipalign → 签名`。签名之后再改动 APK 任何字节，v2/v3 签名立刻失效。

## 6 · apksigner

```bash
keytool -genkeypair -keystore release.jks -alias key -keyalg RSA -keysize 2048 \
        -validity 10950 -storepass "$KS_PASS" -keypass "$KEY_PASS" \
        -dname "CN=Example, OU=Demo, O=Demo, C=CN"

apksigner sign --ks release.jks --ks-pass "pass:$KS_PASS" --key-pass "pass:$KEY_PASS" \
        --ks-key-alias key --min-sdk-version 21 \
        --v1-signing-enabled true --v2-signing-enabled true --v3-signing-enabled true \
        --out out/hello.apk out/aligned.apk
apksigner verify --print-certs out/hello.apk
```

v1（JAR 签名）保证老设备能装，v2/v3 是新设备校验完整性的主力，三者同时开最稳。`--min-sdk-version` 决定签名方案的最低要求，与 Manifest 的 `minSdk` 保持一致。

## 参数速查

在仓库根目录执行，全部可用环境变量覆盖：

| 变量 | 默认 | 说明 |
|---|---|---|
| `TOOLCHAIN` | `~/.local/share/android-toolchain` | 三件套所在目录 |
| `APP` | `examples/hello-webview` | 含 `AndroidManifest.xml` / `res/` / `java/` / `assets/` 的目录 |
| `OUT` | `out` | 中间产物与最终 APK |
| `NAME` | `hello` | 产物名 `out/$NAME.apk` |
| `KS` / `KS_ALIAS` | `./release.jks` / `key` | 签名库；升级必须复用 |
| `KS_PASS` / `KEY_PASS` | `android`（**仅演示**） | 正式发布必须覆盖 |
| `VERSION_NAME` / `VERSION_CODE` | `1.0` / `1` | 覆盖安装时 `versionCode` 必须递增 |
| `MIN_SDK` / `TARGET_SDK` | `21` / `34` | targetSdk 34 时 activity 必须声明 `android:exported` |

```bash
APP=examples/hello-webview NAME=hello VERSION_CODE=2 VERSION_NAME=1.1 bash build_apk.sh
```
